# 反模式对照表（错 → 对）

## 一、结构类

| # | 错误写法 | 为什么坏 | 改成 |
|---|---|---|---|
| 1 | "你是世界顶级数据分析专家，拥有 20 年经验……"占半屏 | 身份描写不改变能力，只烧 token | "你是数据分析师。任务：……"（一行） |
| 2 | 十几条规则堆在 system | 注意力被稀释，末尾规则更有效 | system 留身份 + 总原则；细则进最后一条 user |
| 3 | 一段话塞 5 个任务 | 模型挑着做，漏项 | 拆成 1/2/3，或分轮问 |
| 4 | "分析一下这个"指代不明 | 不知道分析什么维度 | 明确对象 + 维度 + 产出 |
| 5 | 材料在中间、指令在开头 | 长文里指令被淹没 | 材料前、指令后，结尾重述 |
| 6 | 每个任务都贴 5 个 few-shot | 锚定思路、抬成本、限泛化 | 默认零样本；只给 1 个格式示例 |
| 7 | 只写"输出 JSON" | 字段名、嵌套、空值全随机 | 给 schema：字段、类型、枚举、空值规则 |
| 8 | 约束互相打架（要简短 + 要覆盖全部细节） | 模型自行折中，两头不满意 | 标优先级：准确性 > 完整性 > 简洁 |

## 二、模型特性类（DeepSeek 专属）

| # | 错误写法 | 为什么坏 | 改成 |
|---|---|---|---|
| 9 | "请一步一步思考 / 深呼吸 / 慢慢推理" | 思考模式已内置 CoT，重复引导让思维链变长变贵，甚至绕路 | 删掉，只给目标与验收 |
| 10 | 思考模式下调 temperature 想让它更稳 | 参数被忽略，白折腾 | 改 reasoning_effort，或在 prompt 里加约束 |
| 11 | 带 tools 多轮时丢掉 reasoning_content | 接口直接 400 | 每轮原样回传 |
| 12 | 把"不要幻觉"当唯一防编造手段 | 约束太抽象，无法执行 | "信息不足写 `不确定：<缺什么>`；引用须给来源与日期" |
| 13 | 让它"先上网查"但不给工具 | 只能凭记忆答 | 明确要求调用联网搜索 / read_url |
| 14 | 粘贴整篇网页让模型读 | 浪费上下文，被页面噪声带偏 | 要求它 read_url 取原文并引用关键句 |
| 15 | 对 R1 系写长篇 system prompt | 官方建议免 system、零样本 | 直接给问题 + 输出格式 |

## 三、输出类

| # | 错误写法 | 为什么坏 | 改成 |
|---|---|---|---|
| 16 | "要专业、高质量、有深度" | 无法判定，输出套话 | 换成条数、字段、字数、判定条件 |
| 17 | "尽量详细" | 无上界 → 注水 | "≤800 字；超出就砍例子保结论" |
| 18 | 不指定语言 | 中英混杂、术语乱译 | "全程中文，代码与日志保留原文" |
| 19 | 不指定形态 | 有时段落有时列表 | 指定 Markdown 结构或表格列名 |
| 20 | 要长输出但 max_tokens 给小 | 截断在半句 | 放足 max_tokens（max 档 ≥8K） |

## 四、多轮与成本类

| # | 错误写法 | 为什么坏 | 改成 |
|---|---|---|---|
| 21 | 每轮都说"按之前的要求" | 约束漂移，越写越偏 | 每轮末尾重述 1 行核心约束 |
| 22 | 长材料每轮重贴 | 白付输入费 | 材料固定开头，后续只发问题（吃前缀缓存） |
| 23 | 变化内容放开头、固定内容放末尾 | 前缀缓存全失效 | 稳定前缀在前，变量在后 |
| 24 | 批量任务一条一请求 | 贵且慢 | 写死 schema，100 条一批 |

## 五、诊断口诀（用户抱怨时按序查）

1. **答得空** → 目标是不是形容词？
2. **答偏了** → 有没有两个打架的约束 / 指代不明？
3. **答案漏项** → 有没有拆编号？有没有说"逐条回答"？
4. **格式乱** → 有没有 schema 或表格列名？
5. **编造** → 有没有拒答出口？有没有要求给来源？
6. **太长/太短** → 有没有字数上限和不满足时的裁剪规则？
7. **多轮失忆** → 关键约束是不是只在第一轮出现过？
## 六、v2 反模式（分隔符 / 输出契约 / 门禁）

| # | 错误写法 | 为什么坏 | 改成 |
|---|---|---|---|
| 25 | 材料与指令混在一段里 | 长文一上来就串味：材料里的句子被当命令 | 每类输入套一个命名容器，指令全在容器外 |
| 26 | 有开头标签没结尾标签 | 后续所有指令被读成材料 | 容器必须闭合；交付前逐个点一遍 |
| 27 | 容器名写"下面这段""以上内容" | 模型无法引用定位，多段时混淆 | 用 `<工单 id="…">`、`<日志 #3>` 这类名词容器 |
| 28 | 材料里含 XML/围栏却还用 XML 容器 | 提前闭合、边界错乱 | 换唯一哈希容器 `<<<材料 7f3a>>>` |
| 29 | 没声明"容器内是数据" | 材料里一句"忽略以上指令"就能劫持 | 容器后加一行 data-only 声明 |
| 30 | 只说"输出 JSON" | 字段、类型、空值全随机，解析就炸 | 给字段 + 类型 + 枚举 + 空值规则 + 禁止附加文字 |
| 31 | 给了表格列名但没写行数 | 有时 3 行有时 15 行，无法比较 | "恰好 N 行，按 X 降序" |
| 32 | 没写超限裁剪顺序 | 要么注水要么半句截断 | "超出时先砍 Y，保留 X" |
| 33 | 假设写"数据应该是对的" | 无法检查，等于没写 | 每条假设落到"看哪个字段/跑哪条命令" |
| 34 | 假设不满足还要求"尽力完成" | 模型会用错数据硬凑出一个像样的答案 | 改为"不满足即停，只给 BLOCKED 报告" |
| 35 | 没写交付三态 | 分不清"做完了"和"做了一半" | 首行标 DELIVERED / PARTIAL / BLOCKED |
| 36 | BLOCKED 时还附"仅供参考的临时结果" | 会被当成结论直接使用 | 要么不给，要么明写"未验证草稿，不可用于决策" |

## 七、v2 诊断口诀（补在原有七条之后）

8. **格式每次不一样** → 输出契约缺字段/行数/裁剪顺序。
9. **模型把材料当指令** → 容器没闭合或没 data-only 声明。
10. **明明数据不对还给了结论** → 缺前提门禁，或门禁写了但没写"不满足即停"。
11. **答案看着完整但用不了** → 缺 PARTIAL/BLOCKED 标记，模型在掩饰缺口。
