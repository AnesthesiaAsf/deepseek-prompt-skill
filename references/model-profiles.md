# DeepSeek 模型矩阵与参数规则

> 用于决定**思考档位、上下文拼法、是否给示例、参数怎么传**。版本号会滚动更新，规则部分（结构、缓存、回传）比型号更稳定。

## 一、型号矩阵（2026-11 现状）

| 型号 | 参数 | 上下文 | 开放权重 | 定位 | 提示要点 |
|---|---|---|---|---|---|
| **deepseek-v4.1-pro**（V4-Pro 迭代） | 1.6T 总 / 49B 激活 | 1M | MIT | 最强推理与长文 | max 档跑竞赛/规划；长材料吃满前缀缓存 |
| **deepseek-v4.1-flash**（原 deepseek-flash） | 284B / 13B 激活 | 1M | MIT | 日常主力，≈1/3 价格 | high 档覆盖 90% 任务；批量任务首选 |
| **deepseek-v4 / v4-flash 旧名** | 同上 | 1M | MIT | 已并入 v4.1 | 旧名调用可能下线，写 prompt 不受影响 |
| **deepseek-reasoner（R1 血统）** | 671B MoE | 128K | MIT | 纯推理 | 零样本、免 system prompt、boxed 收答案 |
| **deepseek-chat（V3.2 血统）** | 685B | 128K | 否 | 非思考对话 | 这里**需要**明确写步骤与格式；温度可调 |

**默认判断**：用户没指定模型 → 按 v4.1-flash + high 档写。用户提到"最强 / 竞赛 / 复杂规划" → v4.1-pro + max。

## 二、思考档位怎么选

| 场景 | 档位 | 理由 |
|---|---|---|
| 闲聊、改写、翻译、批量分类、抽取 | off / low | 快且便宜，思考反而拖慢、易过度解读 |
| 日常编程、Agent 工作流、分析总结、写材料 | **high（默认）** | 官方推荐的日常档 |
| 竞赛数学、复杂规划、多步推理、疑难 bug、架构重构 | **max** | 思维链会很长，上下文 ≥384K、max_tokens 给足 |

写法差异：
- **off/low**：结构要更硬（明确步骤、字段、格式），因为模型自己不会补推理。
- **high/max**：只写目标 + 验收；**禁止**再写"请逐步分析"，否则思维链被重复引导，变长变贵还可能绕远。

## 三、参数硬规则

| 项 | 规则 |
|---|---|
| temperature / top_p / penalties | **思考模式下传入会被忽略**。想控随机性 → 关思考或换 non-think 端点 |
| non-think 温度参考 | 代码/数学 0.0；数据分析 1.0；通用对话与翻译 1.3；创意写作 1.5 |
| 本地部署 | 官方建议 temperature=1.0, top_p=1.0 |
| max_tokens | max 档放足（≥8K）；思维链算在输出里，给少了会被截断 |
| reasoning_content | 多轮 **带 tools** 时，每轮必须原样回传上一轮 reasoning_content（即使没调用工具），否则 400 |
| JSON 输出 | 用 JSON Mode / 明确 schema；思考模式下把 schema 放在指令末尾 |
| 前缀缓存 | 不变的长材料放开头、变化问题放末尾；多轮复用同一前缀，输入成本≈1/30 |

## 四、能力接口（写 prompt 时可主动要求调用）

| 能力 | 什么时候写进 prompt |
|---|---|
| 联网搜索 | 需要时效信息、价格、政策、版本号。写"检索后标注来源与日期；检索不到就说明" |
| read_url | 用户给了链接。写"读取该 URL 原文，引用时给出关键句" |
| 文件输入（PDF/Office/图片） | 用户有本地文档。写"解析附件，先复述结构再回答" |
| OCR / ASR / TTS | 图片文字、录音转写、朗读 |
| Function calling | Agent 场景。写清工具清单、参数、失败重试策略 |

## 五、常见"模型答得不对"的真实原因

| 现象 | 真实原因 | 改法 |
|---|---|---|
| 答得很空、全是套话 | 目标是形容词（"专业地分析"） | 换成可验收产出（结论 + 依据 + 不确定性） |
| 想到一半跑偏 | 指令里给了两条互相拉扯的约束 | 标优先级："准确性 > 完整性 > 简洁" |
| 输出被截断 | max_tokens 不够 / 材料太长挤掉输出 | 放足 max_tokens，材料压缩或改成分节提问 |
| 每次格式都不一样 | 没给 schema 或没给示例 | 给字段名 + 类型；必要时 1 个格式示例 |
| 中文里夹英文 | 没指定语言 | "全程中文，代码/日志保留原文" |
| 多轮后忘了前文 | 关键约束只在第一条说过 | 每轮末尾重述 1 行核心约束 |
| 工具调用报 400 | reasoning_content 没回传 | 按上文规则原样回传 |

## 六、成本直觉（选档位的依据）

- flash + low ≈ 1 单位；flash + high ≈ 2–3；flash + max ≈ 10+；pro + max ≈ 30+。
- 1M 上下文 + 前缀缓存：同一份长材料问 10 个问题，总成本接近"1 次输入 + 10 次输出"。
- 批量任务（分类/抽取/打标）：写死 schema + off 档 + 分批 100 条一请求，不要一条一请求。
